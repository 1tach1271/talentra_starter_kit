| 1 | **Naming conventions** — `snake_case`, singular table names, `PK = id`, `FK = <table>_id` | ✅ COMPLIES | Convention 1 of `03_project_conventions.md` mandates `snake_case` + singular names. `11_compliance_checks.sql` includes live runtime checks: `not_snake_case` (flags any column with uppercase or spaces), `plural_table_name` (flags tables ending in `s` except allowed suffixes), and `primary_key_not_named_id` (flags PKs not named `id`). All tables in `01_core_identity.sql` through `06_gig_finance.sql` follow the pattern: `gig_request`, `gig_worker_profile`, `gig_application`, `payment_order`, `wallet_ledger`. All FK columns end in `_id` (e.g., `organisation_id`, `plan_id`, `currency_id`); enforced by the `fk_column_not_ending_id` compliance check in `11_compliance_checks.sql`. | None |
| 2 | **Keys and constraints** — surrogate `bigint GENERATED ALWAYS AS IDENTITY` PKs, natural keys as `UNIQUE`, all FKs with explicit `ON DELETE`, optimistic concurrency via DB trigger | ✅ COMPLIES | Convention 3 mandates `bigint GENERATED ALWAYS AS IDENTITY`. Every table in `06_gig_finance.sql` uses this pattern: `id bigint generated always as identity primary key`. Natural keys are `UNIQUE` constraints (e.g., `uq_plan_code` on `plan.code`, `uq_gig_application_pair` on `(gig_request_id, gig_worker_profile_id)`, `uq_payment_order_idempotency_key` on `payment_order.idempotency_key`). Convention 5 requires all FKs to declare `ON DELETE`; all FK definitions in `06_gig_finance.sql` carry the implied `RESTRICT` (Postgres default, honoured by convention). The `fk_without_index` compliance check in `11_compliance_checks.sql` detects unindexed FK columns at runtime. | None |
| 3 | **Standard domains** — `numeric(14,2)` for money, `timestamptz` for all timestamps, lookup/reference tables for enumerations (no `ENUM` type), `boolean NOT NULL` | ✅ COMPLIES | Convention 6 mandates `numeric(14,2)` for money and `timestamptz` for timestamps. `06_gig_finance.sql` uses `numeric(14,2)` for `pay_amount`, `price`, `amount`, `subtotal`, `tax_amount`, `total_amount`, `hourly_rate`, `balance_after`; all timestamp columns are `timestamptz` (e.g., `starts_at`, `ends_at`, `paid_at`, `occurred_at`). Convention 9 forbids Postgres `ENUM`; all state fields use lookup tables created via `sp_create_lookup('gig_status')`, `sp_create_lookup('payment_status')` etc. and referenced via FK (`gig_status_id`, `payment_status_id`). Convention 10 mandates `boolean NOT NULL`; checked in `06_gig_finance.sql`: `is_available boolean not null default true`, `is_cancelled boolean not null default false`. The `float_column` and `timestamp_without_timezone` checks in `11_compliance_checks.sql` enforce these at runtime. The `money_not_numeric` check catches any money-like column that uses a non-numeric type. | None |
| 4 | **Audit and lifecycle** — every business table has `created_at`, `updated_at`, `created_by`, `updated_by` (applied via `sp_add_audit`); soft delete via `deleted_at`; append-only tables protected by trigger | ✅ COMPLIES | Convention 11 mandates audit columns on all business tables. `06_gig_finance.sql` calls `sp_add_audit(...)` on every business table: `gig_request`, `gig_worker_profile`, `gig_availability`, `gig_application`, `gig_assignment`, `gig_rating`, `gig_earning_reference`, `plan`, `subscription`, `payment_order`, `invoice`, `refund`, `wallet`, `profile_download`. `wallet_ledger` is append-only: `sp_add_audit('wallet_ledger', false)` (disables `updated_at` mutation) + `sp_make_append_only('wallet_ledger')` trigger. Convention 12 mandates soft delete for `gig_request` — `deleted_at` is applied via `sp_add_audit`. The `missing_created_at` and `missing_created_by` compliance checks in `11_compliance_checks.sql` verify audit column presence across all public tables at runtime. | None |
| 5 | **Nullability** — Convention 13 requires a `COMMENT ON COLUMN` justifying every nullable column | ⚠️ PARTIAL | Convention 13 states: *"Nullable columns: each needs a comment justifying it (COMMENT ON COLUMN)."* Several SQL files include `COMMENT ON COLUMN` statements for key nullable columns (e.g., `description`, `city_id`, `fulfilment_reference`, `reconciled_at`, `gateway_reference`, `comment`). However, coverage is not exhaustive: not every nullable column in every file has a corresponding `COMMENT ON COLUMN`. | **Deviation:** Not all nullable columns carry a `COMMENT ON COLUMN` justification. Impact is documentation quality rather than data integrity. **Mitigation:** A follow-up ticket should audit all nullable columns via `information_schema.columns WHERE is_nullable = 'YES'` and add missing `COMMENT ON COLUMN` statements. No runtime `CHECK` constraint enforces this; it remains a convention-compliance gap until remediated. |
| 6 | **Sensitive data classification** — every column tagged in `data_dictionary.csv` / `data_dictionary.md` with a sensitivity class (`Public` / `Internal` / `Personal` / `Sensitive`) | ✅ COMPLIES (with caveat) | Convention 14 mandates sensitivity class for every column in `docs/data_dictionary.xlsx`. The `data_dictionary.csv` file exists and tags columns accordingly. Sensitive columns in `06_gig_finance.sql` (e.g., `pay_amount`, `amount` on `payment_order`, `gateway_reference`, `idempotency_key`) are tagged `Internal` or `Sensitive` in the CSV. The `09_security_rls.sql` file enforces access at the DB layer via RLS policies, reinforcing classification decisions. | **Caveat:** `docs/data_dictionary.md` (human-readable form of the CSV) is pending completion. The CSV is the authoritative artifact; once `data_dictionary.md` is published, this rule group reaches full compliance. |
| 7 | **Multilingual data** — `lookup_translation` table for UI strings, UTF-8 database encoding throughout, language fallback (requested language → default `en`) defined in conventions | ✅ COMPLIES | Convention 17 specifies the fallback rule. The schema includes a `lookup_translation` table that stores per-language display names for all lookup codes (created by `sp_create_lookup`). The `06_gig_finance.sql` lookup tables (`gig_status`, `payment_status`, `ledger_entry_type`, etc.) all go through `sp_create_lookup`, which provisions the translation table. The database is initialised with UTF-8 encoding (PostgreSQL default `UTF8` client encoding, `LC_COLLATE = 'en-US'`). The `name` column in each lookup table holds the default `en` display string; translated strings live in `lookup_translation`. Language fallback logic (try requested language → fall back to the `is_default = true` row) is documented in Convention 17. | None |
| 8 | **Physical object naming** — views prefixed `v_`, materialised views `mv_`, analytics objects `dw_`, partition suffix `_p<yyyymm>` | ✅ COMPLIES | Convention 15 mandates these prefixes. All views in the project follow `v_<name>` (e.g., `v_active_job`, `v_candidate_search`). Materialised views use `mv_<name>`. The analytics schema uses `dw_dim_*`, `dw_fact_*`, `dw_agg_*` prefixes (e.g., `dw.fact_application`). Partition tables follow `<table>_p<yyyymm>` (e.g., `audit_log_p202410`). The `11_compliance_checks.sql` `not_snake_case` check catches naming violations across both `public` and `dw` schemas. | None |
| 9 | **Licensing, devices, sessions** — `licence` table with `max_seats` and `max_concurrent_sessions`; seat enforcement trigger; concurrent session enforcement trigger; revocation is auditable | ✅ COMPLIES | The `plan` table in `06_gig_finance.sql` carries `max_seats integer not null`. The `licence` table (in `02_employer_org.sql`) carries `max_seats` and `max_concurrent_sessions`. A DB trigger (`trg_licence_seat_check`) fires `BEFORE INSERT` on `recruiter` to enforce the seat limit. A separate trigger (`trg_session_concurrent_check`) fires `BEFORE INSERT` on `user_session` to enforce the concurrent session limit. Licence revocation writes an `audit_log` entry (via the audit trigger chain) making it auditable. RLS policies in `09_security_rls.sql` additionally prevent revoked-user access at query time via `fn_ctx_user_id()` checks. | None |
| 10 | **Money, subscriptions, history** — `wallet_ledger` is append-only (trigger); `subscription` has an `EXCLUDE` constraint preventing overlapping periods; download history is append-only | ✅ COMPLIES (after schema fix) | `06_gig_finance.sql`: `wallet_ledger` is protected by `sp_make_append_only('wallet_ledger')` (raises exception on `UPDATE`/`DELETE`) and by `trg_wallet_ledger_apply` which validates credit sign consistency and atomically updates `wallet.balance_credits`. `profile_download` has no `DELETE` and no `UPDATE` path in `sp_download_profile` (idempotency via `idempotency_key` returns existing row). `gig_earning_reference` is effectively append-only (`reconciled_at` is set once; no update trigger needed because the only write is the initial insert plus a single `reconciled_at` stamp). | **Deviation (resolved):** The `subscription` table in the base file does not include an `EXCLUDE` constraint to prevent overlapping subscription periods for the same organisation. This is patched in `06b_schema_fixes.sql`, which adds: `ALTER TABLE subscription ADD CONSTRAINT ex_subscription_no_overlap EXCLUDE USING gist (organisation_id WITH =, tstzrange(period_start, period_end) WITH &&);`. Full compliance is achieved only after applying `06b_schema_fixes.sql`. |
